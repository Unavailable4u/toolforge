Security, in plain words

ToolForge is built so that a mistaken or hostile tool is contained and recorded, but it is not a guarantee against every attack.

What it is built to do

  • Run tool code only inside the sandbox, never on the host.
  • Keep the network closed unless a person approved the exact hosts.
  • Keep secrets out of the sandbox. A broker adds them to approved requests.
  • Give an agent no way to approve, promote, release, roll back or delete. A test reads the server's source to keep it that way.
  • Listen on the local machine only, unless a bearer token is set.
  • Record every step in a hash-chained ledger, so an edited line breaks the chain.

What it does not promise

  • A container is not a virtual machine. A flaw in Docker or the kernel could defeat it.
  • The gates look for known kinds of trouble. A clever tool can still pass them, so the sandbox is the real wall.
  • A ledger shows tampering. It does not stop someone with full access to the machine.
  • The detector for hostile text is a heuristic, not a filter you can rely on alone.
  • It has one operator and no user accounts.
  • The Docker Compose set-up was written without a Docker daemon to try it on.
