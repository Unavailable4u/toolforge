How it fits together

Five parts, with a wall between the agent that asks for tools and the room where tool code runs.

  1. The server

    The only thing an agent can reach. It offers a short, fixed list of tools and refuses everything else. It cannot approve, promote or delete anything.

  2. The gates

    The inspection line. It decides how far a new tool is trusted and writes down why.

  3. The registry

    The shelf. Versions of tools, their manifests, their track records and their reports.

  4. The sandbox

    A locked room made by MiniLocker on top of Docker. Tool code never runs anywhere else.

  5. The operator

    You. A command line and a local dashboard, kept apart from the server so an agent cannot reach them.

Who is trusted

The operator and the host are trusted. The agent is not: it is treated as a stranger who might be confused or manipulated. Tool code is hostile until proven otherwise, and it stays inside the sandbox. Text that a tool returns is treated as hostile too, and is fenced and flagged before a model reads it.
