The idea, in four steps

A new tool is inspected, tested and tried in a locked room before it goes on the shelf, and every inspection is written down.

Think of a tool shop with an inspector at the door. Nothing reaches the shelf until it has been inspected, tested and tried in a room with no windows. Every inspection goes into a notebook where an edited page would show.

  1. 1 Forge

    Someone brings a new tool to the shop. The agent writes the tool, its tests and a label, called the manifest, that says what the tool may touch.

    For example: asked to total a column in a SQLite file, an agent forges a small query tool.

  2. 2 Verify

    The inspector works through a series of stations, the gates. They read the code, build it, run its tests, feed it odd inputs, let a second AI try to break it and probe it in a locked room. A person approves any request for the network or a secret.

    For example: a tool that opens a fake credentials file is caught reaching for it.

  3. 3 Run

    Every use happens in a locked, windowless room: a hardened container. The tool gets only what its label says, and the network stays closed unless a person approved the exact hosts.

    For example: a tool with no network permission cannot call out, whatever its code tries.

  4. 4 Reuse

    The next agent looks on the shelf first. Tools have versions and a track record. A broken one is repaired as a new version and inspected again, and a bad one can be rolled back.

    For example: the SQLite tool from step one answers questions about a different database, with no new build.
